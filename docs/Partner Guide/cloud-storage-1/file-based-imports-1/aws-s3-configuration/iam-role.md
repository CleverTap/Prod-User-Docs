# Overview

This document covers configuring your Amazon S3 connection on CleverTap using an IAM Role. With this method, CleverTap authenticates with its own AWS identity, and you grant that identity access to your bucket by applying a bucket policy that the CleverTap dashboard generates for you. No IAM user or access key is required, and no credentials are stored in CleverTap. It applies to both import and export connections.

The generated policy differs by connection type:

- **Import**: grants CleverTap's IAM role `s3:GetObject` and `s3:ListBucket` on your bucket (read access).
- **Export**: grants CleverTap's AWS account `s3:PutObject*` on your bucket path (write access).

<Callout icon="📘" theme="info">
  ### Note

  CleverTap's AWS account ID differs by CleverTap region. Always copy the policy from your own dashboard; do not reuse a policy from documentation, another project, or another region.
</Callout>

Before you begin, complete Create an S3 Bucket on AWS and Add the Bucket on the CleverTap Dashboard in [Amazon S3,](doc:amazon-s3) and select the _IAM Role_ under _Configure with_.

The following are the major steps to configure your Amazon S3 connection using an IAM Role:

1. [Copy the IAM Policy from the CleverTap Dashboard](#copy-the-iam-policy-from-clevertap)
2. [Apply the IAM Policy to the S3 Bucket on AWS](#apply-the-iam-policy-to-the-s3-bucket-on-aws)
3. [Configure the Connection on CleverTap](#configure-the-connection)

<Callout icon="🚧" theme="warn">
  ### Important

  CleverTap's AWS account ID differs by CleverTap region. Always copy the policy from your own dashboard, and do not reuse a policy from documentation, another project, or another region.
</Callout>

The configuration involves copying the generated policy, applying the policy to your S3 bucket, and saving the connection in CleverTap. For a comparison of all three methods, refer to [Choose Configuration Method](doc:amazon-s3#choose-configuration-method).

- An S3 bucket already created on AWS. Refer to [Create an S3 Bucket on AWS.](doc:amazon-s3#create-an-s3-bucket-on-aws)

- The bucket details are entered on the CleverTap dashboard with the correct Folder value and IAM Role selected. The Folder value is inserted into the generated policy.

- AWS console access with permission to edit the bucket policy (`s3:PutBucketPolicy`) on the bucket.

## Configure with IAM Role

### Copy the IAM Policy from CleverTap

This section covers copying the IAM policy generated by the CleverTap dashboard.&#x20;

CleverTap pre-fills the policy with its AWS principal and the bucket name you entered under Folder.

To copy the policy, perform the following steps:

1. On the Connect to _Amazon S3_ for **import** or Connect to Amazon S3 for **export** page, confirm that Folder contains your exact bucket name. The policy regenerates when _Folder_ changes.
2. Under _Configure with_, select **IAM Role**.
3. Copy the generated IAM policy using the copy icon.&#x20;

<Callout icon="📘" theme="info">
  ### Note

  The CleverTap dashboard labels this an IAM policy. On AWS, you apply it as the bucket policy of your S3 bucket (a resource-based policy), not as an IAM identity policy. Keep this page open; you return to it to save.
</Callout>

### Apply IAM Policy to S3 Bucket on AWS

Applying the policy as a bucket policy on AWS grants CleverTap access to your bucket. For more information about AWS bucket policies, refer to [Adding a bucket policy using the Amazon S3 console](https://docs.aws.amazon.com/AmazonS3/latest/userguide/add-bucket-policy.html).

1. Log in to your AWS console and go to **S3**.

2. Select your bucket from the _Buckets_ page.


   <Image src="https://files.readme.io/1f50b88f2ed9f96ffbb29ba9cbb156ae35f9ab2a5dc7af1fa14e173b5add03a7-select_bucket.png" align="center" caption="Select Bucket - AWS S3" border={true} />


3. Go to the **Permissions** tab and click **Edit** under _Bucket policy_.


   <Image src="https://files.readme.io/d91969dac48b7dcdb004da8885d9571f8177955d68b74f9f45b3773b2d8aac02-buket_policy.png" align="center" caption="Permissions and Bucket Policy - AWS S3" border={true} />


4. If the bucket has no existing policy, paste the policy you copied from CleverTap.

5. If the bucket already has a policy, add the statements from the CleverTap policy to the existing `Statement` array. Do not replace the existing policy; replacing it removes permissions that other systems depend on.

6. Click **Save changes**.


   <Image src="https://files.readme.io/a8e949397872f4f74e2ba4b814f110191d59518694b7e21bca84e9aee113f7ca-edit_bucket_policy.png" align="center" caption="Paste IAM Policy and Save Changes" border={true} />

# Troubleshooting

| Issue                                                                              | Cause                                                                                                                                      | Resolution                                                                                                                                |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| AWS rejects the bucket policy with "Invalid principal"                             | The policy was copied from another source, or the principal account ID was edited.                                                         | Copy the policy again from your CleverTap dashboard without modification.                                                                 |
| AWS rejects the bucket policy with a resource error                                | The bucket name in the policy does not match the bucket you are editing.                                                                   | Fix _Folder_ on the CleverTap dashboard, copy the regenerated policy, and paste again.                                                    |
| Existing integrations lose access after saving the policy                          | The existing bucket policy was replaced instead of extended.                                                                               | Restore the previous statements and add the CleverTap statements to the Statement array.                                                  |
| **Save** or **Test Connection** fails on CleverTap even though the policy is saved | _Block all public access_ is on and the policy includes a wildcard principal, or the region on CleverTap differs from the bucket's region. | The CleverTap policy uses a specific principal and is compatible with _Block all public access_. Confirm the _Region_ value on CleverTap. |

# Verification Checklist

Confirm the following before using the connection in production:

- Folder on the CleverTap dashboard matches the AWS bucket name exactly.
- The bucket policy on AWS contains the CleverTap statements and all pre-existing statements.
- The principal in the bucket policy matches the one shown on your CleverTap dashboard.
- **Test Connection** (import) or **Save** (export) succeeded on the CleverTap dashboard.
